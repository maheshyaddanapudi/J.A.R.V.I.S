# Arg-validation experiment (tools.validateArgs) — 2026-08-29

**Question:** I claimed unvalidated tool args were a "minor" gap after finding that a
malformed call fails inside the tool body with a raw JS error (contained by the loop,
never a crash). The user's challenge: *how do we know it's minor without running
experiments?* — so the default is decided by measurement, not opinion.

**Mechanism (pushed as `c197d7e`):** `tools.validateArgs` — catalogued boolean,
**default off** (= prior behavior, unchanged). On: every gated tool call is checked
against the tool's declared `inputSchema` (ajv) at the loop's single choke point,
BEFORE disclosure/policy/approval; a mismatch refuses cleanly with the field-level
reason; an uncompilable schema fails OPEN (our bug must never block a tool). 4 tests
pin both behaviors; suite 437/437.

## Design

Two arms on fresh, separate scratch DBs, identical batteries, Sonnet-5 serving
`planning` (the agent role): 12 agent objectives each — 6 normal (base rate) and 6
*provocation* tasks phrased to invite wrong arg shapes ("remember the **fact**
that…" vs the actual `statement` arg — the exact confusion a human, me, fell into
by hand). Metrics per arm: malformed calls per 100 tool calls (crash-shaped
summaries in arm A, `invalid args for` refusals in arm B), recovery rate, task
success, and — the arm-B-specific risk — false refusals of valid calls.

## Results

| | Arm A (off) | Arm B (on) |
|---|---|---|
| Runs / task success | 12 / 12 | 12 / 12 |
| Tool calls | 14 | 14 |
| Malformed (any kind) | 0 | 0 |
| Recoveries needed | 0 | 0 |
| False refusals of valid calls | — | 0 |

Both arms took byte-equivalent paths, including the one multi-step task (fact
correction → recall then correct with the exact factId, the D-0062 read-then-write
contract, in both arms). Raw per-run data: the battery script + JSON summaries are
preserved in the session scratchpad (one-off probe, not a recurring bench).

## Decision

**Default stays `off`.** With a schema-guided frontier model the measured malformed
rate is zero and validation is pure overhead (albeit ~free); flipping it on also
showed zero cost (no false refusals), so users who want belt-and-braces can enable
it harmlessly in `/settings`.

**Honest caveats:** (1) n = 28 tool calls at zero observed events bounds the
per-call rate below ~11% at 95% confidence — this proves "rare with Sonnet-5",
not "never". (2) The population where the flag most plausibly earns its keep was
NOT measurable here: the Mac's local models (qwen3.6 serving
`tool_selection`/`agent_routing`), which emit malformed tool calls far more often
than frontier models. **Re-run this battery on the M3 Max with local models at
bring-up; set the default from that measurement.** The battery design (normal +
provocation split, both-arm metrics incl. false refusals) transfers as-is.
